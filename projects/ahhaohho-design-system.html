From Tokens to Motion

Foundations · Design Tokens as Data · Motion as the Signature

I built the AhhaOhho Design System from the ground up: a token-based foundation of color, type, space, and motion, all managed as designer-editable data that generates Flutter and React code. On top of that foundation sits the part that makes a children's product feel alive — an interactive Rive & Lottie motion layer. Foundations first, motion as the highlight. The demos further down are real production files. Try them.

The Foundation

Before a single component, there's a language: one palette, one type scale, one spacing grid, one set of motion curves.

Everything in the system resolves to tokens. Colors follow a primitive → semantic structure, named property.role-variant-state (e.g. fg.neutral, bg.brand-highlight), so a component never references a raw hex. The same discipline runs through type, spacing, radius, elevation, and motion — one source, every platform.

02

Managed as a System

An animation library rots without a system around it. This one lives in the same repository the app ships from.

Every motion asset is registered in a typed library (data/rive.ts, data/lottie.ts) with its state machine, inputs, and usage notes. Adding an entry publishes an interactive playground card on the docs site, where developers test triggers and bindings before wiring them into Flutter. Motion timing lives as design tokens alongside color, spacing, and typography. All of it is designer-editable JSON, and Flutter and React code is generated from it.

03

Where Motion Earns Its Place

Children don't read interfaces. They poke them, and they trust what answers back.

We tested with more than 3,000 children, and the pattern never changed: kids explore by touching everything, and a static screen reads as broken to a 9-year-old. So this design system treats motion as a first-class layer. Every button press, progress tick, reward, and character moment is a designed, reusable animation asset rather than something a developer improvises at the end.

The system speaks two motion vocabularies. Macro motion covers page transitions, modals, and celebrations that run longer than 200ms. Micro motion covers button presses, focus, and feedback under 200ms. Each has its own timing tokens.

04

Interactive Motion — Rive

These are not videos of animations. They are running state machines, and the same files ship in the Flutter app.

Complex interactive animation is built in Rive. Each .riv file carries its own state machine, so the interaction logic for pressed, valid, progress, and celebration states lives inside the design asset itself instead of being re-implemented on every platform. Progress components expose data bindings: the app writes a number, and the animation responds. Try the four production files below.

06

Impact & Reflection

Putting interaction logic inside the animation files changed the contract between design and engineering. Designers now own how the product feels at 60fps, and developers consume assets that already know their own states. Motion also stopped being the first thing cut under deadline, because it ships as part of the component instead of as polish at the end.

The craft lesson: for children, expressive motion and system discipline are not in tension. The playful moments stay playful at scale because the durations, easings, and states underneath them are tokenized.
